# Beatbox v1.0.0-usb-whitebox.1：同配置网页与 USB 白盒快照

保存日期：2026-10-02。运行版本仍为 `1.0.0`。本次追加固定标签，不移动、覆盖或删除 `v1.0.0` / `v1.0.0-backup.1`，也不修改旧发布附件。

## 保持不变

- 日常蓝牙连接：BLE GATT，浏览器本地钥匙与 HMAC 挑战；新浏览器仍需在停止、非录制状态按住实体 S7 三秒开放登记窗口。
- USB 备用：Web Serial / JSON Lines，115200 波特率，DTR 开、RTS 关；同一串口只能由一个程序占用。
- Beatbox 固件及分区：应用镜像地址 `0x430000`；不改变 factory、bootloader、分区表、NVS 或启动选择。
- 原固件镜像 985,264 字节，SHA-256：`dea3720fbe7e20b45eaed2784bea83cc235f8046dd11ec80223afb1b1fe784f8`。
- 网页布局、音色、默认节奏与当前交互配置不变。本次使用新网页不需要烧录。

## 本次保存的新增内容

- 安全 USB 白盒诊断：打开和读取错误、接收字节/块/行计数、按键及状态接收/应用对照。
- 分块 USB 消息、S7 状态同步与日志不暴露原始敏感内容的回归测试。
- 连接、验收和恢复说明；不发布浏览器钥匙、原始设备日志或设备唯一标识。
- 固定源码 ZIP、Git 历史 bundle、生产网页 ZIP、恢复指南与 SHA-256 清单；固件更新包复用原先已验证的文件，不重新构建固件。

## 已验证与未验证

- 软件：40 项网页自动化测试、TypeScript、Vite 生产构建通过；隔离 Playwright 模拟 USB 回归覆盖桌面 1600×1100、手机 390×844、S1/S5 高亮及 S7 A/B/A；无测试页面运行错误。
- 固件：45 个源文件/配置文件与原固定发布版指纹一致；原固件包和发布附件校验通过。该核对只读本地文件，没有访问开发板。
- 实机：2026-10-01 本地 USB 的 S1/S5 按下/松开正确反映到网页高亮；停止、REC 关闭时短按 S7，设备和网页同步 B → A → B → A；用户确认“都有亮，也有切换”。
- 恢复后独立 18 秒采集收到 13,528 字节、44 条状态消息，无解析错误；这轮 USB 恢复没有烧录、清 NVS 或修改启动选择。
- 仍未确定此前 USB 失效的具体根因。全键、编码器/三档速度/Fill 全流程、自动重连、断电信任、所有浏览器和长期稳定性仍待验收。
- 本地硬件验收不能代替 GitHub Pages 新网站的真实硬件验证；网页上线的文件核对也不是硬件验证。

## 下载与恢复

1. 日常使用：[在线网页版](https://xingchen-stars.github.io/easyinput-beatbox/)。USB 连接前停止独立串口监听并断开其他标签的 USB；蓝牙可仅使用 USB 供电。
2. 当前源码：[固定标签](https://github.com/Xingchen-stars/easyinput-beatbox/tree/v1.0.0-usb-whitebox.1)，或对应 Release 的源码 ZIP / Git bundle。恢复 Git 历史可使用 `git clone <下载的.bundle文件> <新的恢复目录>`；已有项目不用覆盖。
3. 网页静态包：解压到新的目录，通过 localhost 或 HTTPS 静态服务器提供；直接双击 HTML 不代表 Web Bluetooth / Web Serial 能使用。
4. 固件：只有需要恢复板上程序时，才按包内 [烧录与恢复指南](../flashing-and-recovery.md)重新核对设备、分区和授权。不要运行单工程默认 `idf.py flash`，不要因网页更新重烧或清空整块 Flash。
5. 校验：运行包内 `verify_release.ps1` 或将 `SHA256SUMS.txt` 与文件的 SHA-256 对照。校验成功证明下载文件完整，不证明新一次烧录或硬件验收成功。

原固定版完整附件仍见 [v1.0.0 Release](https://github.com/Xingchen-stars/easyinput-beatbox/releases/tag/v1.0.0)，离线源码依赖锁修正见 [backup.1 说明](v1.0.0-backup1.md)。安全边界继续保留：应用 HMAC 授权不等于 BLE 链路加密。
